# 《消失的星空》结构性重构诊断 v1

> 文档性质：已发布故事的重构前诊断与新版编辑方向
> 检查对象：线上 v1.0、现有设计文档、正文、方法、数据文件及生产代码
> 状态：编辑方向已于 2026-07-28 确认；生产网页尚未修改
> 日期：2026-07-28

## 1. 结论

《消失的星空》目前是一篇完成度尚可的光污染科普页面，但还不是一篇达到 Pudding 水准的数据故事。

问题不只是技术栈较旧，也不只是视觉不够精致。更根本的问题是：

1. **故事没有围绕一个独特、可被数据证明的发现推进**，而是依次介绍全球比例、代际变化、可见极限、物理机制、地点差异、生态影响和照明治理；
2. **同一组真实对象没有贯穿全文**，星空、地图、卫星、人眼、鸟类和路灯实验互相替换，形成“滚动中的模块展览”；
3. **多个核心互动改变的是手工设定的情景参数，而不是真实数据维度**；
4. **设计文档承诺了真实星表、真实地理基线和数据校验，生产版本仍使用模拟星点、示意地图和硬编码指数**；
5. **页面把不确定性写进了说明，却没有让不确定性改变视觉本身**。

这次重构应保留“星星没有消失，消失的是夜晚”这一情感核心，但必须重新建立编辑命题、证据链和视觉语法。不能只把现有静态 HTML/CSS/JavaScript 迁移到 Svelte，再把同样的模块做得更顺滑。

## 3. 当前版本哪里有效

重构不应推倒所有内容。以下部分值得保留：

| 现有元素 | 保留理由 | 新版处理 |
|---|---|---|
| “星星没有消失。消失的，是夜晚。” | 能把抽象环境问题转化为感知经验 | 保留为中心句，但不再承担唯一论点 |
| 同一天区、同一投影、只改变可见条件 | 是公平比较的正确方向 | 升级为真实星表与可复现观测框架 |
| 暗星先失去对比、亮星最后保留 | 是全文最有潜力的视觉语法 | 变成贯穿全文的“可见阈值” |
| 9.6% 年均天空辉光增长与 18 年情景 | 能把慢变化转译为一代人的时间 | 使用论文口径和真实星表重新计算，不再线性插值 |
| 卫星与人眼测量不同对象 | 是重要的方法论提醒 | 提前进入证据结构，不再作为孤立信息卡 |
| “减少光污染不等于关掉城市” | 能避免错误二选一 | 用真实照明路径和可验证原则替代任意指数 |
| 返回夜空的结尾 | 具备观察行动与情感回环 | 返回开场的同一个星座和同一地点 |

## 4. 当前版本的结构性问题

### 4.1 编辑命题仍是“关于光污染的所有知识”

现有页面的实际结构是：

> 光污染很普遍 → 一代人会少看很多星 → 为什么会这样 → 不同地点不同 → 数据源不同 → 鸟也受影响 → 灯可以改进

这是一条合理的科普目录，但没有一个必须按此顺序经历的视觉论证。删掉任意两个模块，中心结论几乎不变；交换多个模块的顺序，故事也仍然成立。这说明章节之间主要是主题并列，而不是证据递进。

新版需要一个更窄、更可见的命题：

> 城市夜空的损失不是所有星星一起变暗，而是一条“可见阈值”穿过同一片真实星空：亮星仍在，让人误以为什么都没变；阈值每移动一点，却会让大量暗星跨过肉眼边界。

这条命题能把星表、天空辉光、代际变化、空间差异和照明治理放进同一套视觉语法。

### 4.2 缺少具体开场对象

当前开场是“如果你长期住在大城市”，属于概括性的第二人称。读者尚未认识一个具体地点、时间、星座或人物，就被要求接受“你可能从未见过银河”。

新版建议从一个固定、可复现的观察切片开始：

> 同一晚、同一时刻、同一个猎户座，从较暗夜空移动到纽约强光环境时，哪些星依次失去可见性？

猎户座不是装饰性背景，而是第一组真实数据实体。读者先认识几颗亮星和较暗星，再看到它们进入完整星表、星等分布和城市空间。

最终地点、日期、时刻和天区将在证据阶段根据星表、可见性和叙事清晰度确认；本阶段不提前制造精确值。

### 4.3 中央视觉语法被多个孤立模块打断

现有页面前半段使用星点，随后切换为：

- 城市剖面；
- 粗略纽约地图；
- 卫星/人眼信息卡；
- 五个星空窗口；
- CSS 鸟群；
- 路灯控制台。

这些视觉对象没有从前一状态演化而来，也没有在后一状态中继续存在。读者每到一章都要重新学习一套界面。

新版必须让以下对象持续存在：

- **视觉名词：**同一片真实星空中的恒星；
- **视觉动词：**恒星跨过可见阈值，逐颗消失或返回；
- **比较框架：**固定天区 + 星等轴/可见阈值 + 观测地点；
- **机制转场：**从“哪些星消失”反向追踪到“哪部分地面光抬高了背景”；
- **回环：**结尾回到开场的同一星座，而不是换一片泛化的模拟星空。

### 4.4 互动没有改变真实数据维度

#### 可见极限滑杆

方向正确，但当前星空来自 100 余个手工坐标和视星等值。它只能说明“程序让一些点消失”，不能让读者理解真实星空中哪些星跨过阈值。

#### 地点—星空联动

地点名称真实，但可见极限区间是环境类型情景；地图是手绘相对形状；点位没有连接到人工天空亮度模型、观测记录或数据年份。

#### 鸟类互动

鸟类轨迹由 CSS 序号规则生成，开灯后部分轨迹自动偏转。它解释了一个可能机制，却没有展示研究中的时间、地点、鸟群数量或真实观测变化。

#### 照明治理实验室

“相对天空辉光 95”等指数来自硬编码加减分；每项措施的权重没有模型或研究依据。即使标注“示意指数”，读者仍会自然把数值理解为可比较的量。

新版原则：

- 真实星表控制星的位置、视星等和星名；
- 真实或明确模型化的天空亮度控制阈值；
- 真实地点坐标连接到有年份和空间分辨率的环境数据；
- 没有定量模型支撑的照明建议只展示光路被切断的方向变化，不再输出伪精确分数；
- 生态案例若保留，必须使用一个有明确事件和观测量的案例，不再保留装饰性鸟群开关。

### 4.5 文档承诺与生产实现不一致

| 设计承诺 | 当前实现 | 风险 |
|---|---|---|
| 使用真实星表 | 手工确定性星点数组 | “真实规则驱动”表述过度 |
| 250→100 与统一函数、星等阈值一致 | 线性年龄、线性阈值、线性星数函数 | 视觉与论文情景不是同一计算 |
| 地点使用人工天空亮度模型并校验 | 硬编码环境类型区间 | 地点比较不可复核 |
| 五地真实比较 | 生产版改成五类泛化环境 | 失去地理和社会含义 |
| 治理展示方向性改善 | 任意权重汇总为 16—96 指数 | 视觉权威超过证据 |
| 8—10 分钟内容深度 | 页面正文偏短，多段依赖视觉占屏 | 实际发现数量不足 |

重构必须先修复证据与实现的对应关系，再谈动画精度。

### 4.6 移动端与无障碍仍是“缩小版桌面”

当前移动规则主要是把双栏改为单栏、缩短 sticky 高度、把小倍数改为两列。尚未针对手机重新设计：

- 星座标签密度；
- 文字与星空的遮挡关系；
- 地点选择顺序；
- 滑杆的手指精度；
- 长滚动中的定位感；
- 低性能设备上的 Canvas 更新。

`prefers-reduced-motion` 只关闭部分动画；Hero 直接停在中间状态，读者没有获得等价的“暗夜 → 城市夜空”解释。无 JavaScript 时，多个核心 Canvas 也缺少可读的静态替代。

## 5. 建议的新编辑方向

### 5.1 驱动问题

> 当城市夜空只“亮了一点”，为什么我们会失去这么多星？

### 5.2 暂定论点

> 人工天空辉光推动一条可见阈值穿过真实星空；由于暗星数量远多于亮星，阈值的小幅移动会造成不成比例的星空损失，而仍然可见的亮星又会掩盖这种变化。

### 5.3 读者的认识变化

阅读前：

> 光污染就是天空变灰、银河看不见，大城市只能如此。

阅读后：

> 光污染是一条可以测量、会移动的可见边界；我能看懂哪一些星为什么先消失，也能区分真实观测、模型估计和照明设计能改变的部分。

### 5.4 具体开场

建议以一个固定天区中的猎户座开场：

1. 先只显示几颗城市中仍容易看见的亮星；
2. 让读者判断“这是否就是完整的猎户座”；
3. 背景逐渐变暗，同一坐标上的较暗星逐颗返回；
4. 其中一颗具体暗星被保留为全文追踪对象；
5. 这组星随后进入星等轴和完整星表，而不是被另一张图替换。

若数据验证后发现另一星座更适合中文读者、冬夏时段或纽约/深圳双城比较，可在内容证据阶段更换，但必须保持“固定真实天区”的原则。

### 5.5 视觉存在的必要性

这篇故事必须被看见，而不只是被写出来，因为核心关系同时涉及：

- 固定空间位置；
- 恒星视星等分布；
- 天空背景变化；
- 可见阈值移动；
- 同一对象在时间和地点中的状态变化。

读者只有亲眼看见同一批恒星跨过阈值，才能理解“亮星仍在”和“星空已大幅损失”为什么可以同时成立。

## 6. 新版叙事骨架（编辑级，不是详细故事板）

| 章 | 读者发现 | 保持不变的对象 | 新加入的证据 |
|---|---|---|---|
| 1. 你看到的不是完整星座 | 熟悉亮星仍在，但暗星已消失 | 固定真实天区 | 星表、视星等 |
| 2. 一条看不见的边界 | 天空背景决定哪颗星能越过肉眼阈值 | 同一批恒星 | 对比度/极限星等解释 |
| 3. 小幅变亮，大量消失 | 暗星数量多，阈值移动造成非线性损失 | 同一批恒星转为星等分布 | 星数—星等累计分布 |
| 4. 一代人的夜空 | 复合增长如何把阈值推过更多恒星 | 开场星座随年龄持续变化 | Globe at Night 2011—2022 |
| 5. 一座城的多片天空 | 地点改变背景，不改变天上的恒星 | 同一天区、同一时刻 | 人工天空亮度空间数据与点位 |
| 6. 光从地面来到天空 | 路灯方向、反射和光谱改变背景 | 失去的那颗星仍作结果标记 | 照明光路和机构原则 |
| 7. 让哪一些星回来 | 治理不是关灯，而是减少无效光路 | 回到开场星座 | 有证据的 A/B 情景，不输出任意指数 |
| 8. 回到今晚 | 读者重新认识自己看到的“正常夜空” | 开场星座与地点 | 观察指南、限制和下一步 |

这条骨架将现有 12 个场景压缩为 8 个递进章节。减少模块数量，但增加每个发现的证据深度和对象连续性。

## 7. 保留、重做与删除

| 当前模块 | 决定 | 原因 |
|---|---|---|
| Hero 星空消失 | 重做 | 保留情感作用，改为真实星座和具体观察 |
| “超过 80%”大数字 | 下沉 | 可作为背景证据，不再单独占一章 |
| 250→100 代际滚动 | 重算重做 | 保留一代人尺度，改用论文口径和真实星表 |
| 可见极限滑杆 | 融入主视觉 | 不再作为独立演示器，成为贯穿全文的阈值 |
| 城市光穹剖面 | 重做 | 从抽象剖面改为由结果反推光路 |
| 纽约地点地图 | 重做 | 使用真实地理与数据，不再使用相对手绘图 |
| 卫星与人眼“两把尺子” | 融入方法 | 在第一次跨数据源比较时就解释 |
| 五类天空窗口 | 删除独立模块 | 与阈值和地点章节重复 |
| CSS 鸟类开关 | 删除 | 与主线分离且无真实观测量 |
| 生态影响 | 条件保留 | 仅保留一个有数据的具体事件/研究案例 |
| 照明治理指数 | 删除 | 缺乏定量模型，容易形成伪精确 |
| 照明治理互动 | 重做 | 改为真实原则驱动的光路 A/B 比较 |
| 观察式结尾 | 保留重写 | 回到开场星座、地点和那颗暗星 |

## 8. 证据与数据计划

本阶段只确定证据需求，不提前锁定未经核验的数值。

| 场景 | 所需数据 | 候选来源 | 主要风险 |
|---|---|---|---|
| 固定真实天区 | 赤经、赤纬、V 波段视星等、颜色 | Bright Star Catalogue、Gaia 经筛选子集 | 许可、投影、观测时刻 |
| 可见阈值 | 极限星等与背景亮度关系 | 同行评议文献、Globe at Night 方法 | 个体视力、月相、天气 |
| 星数非线性 | 固定天区或全天累计星数分布 | 本地处理的星表 | 星表完整度与裸眼口径 |
| 代际变化 | 2011—2022 人眼天空辉光趋势 | Kyba et al. 2023、Globe at Night | 全球平均不能冒充城市预测 |
| 全球背景 | 人工天空亮度人口暴露 | Falchi et al. 2016 | 数据基线年份较早 |
| 城市空间 | 点位天空亮度模型、附近观测 | World Atlas、Globe at Night | 空间分辨率与观测稀疏 |
| 地面夜光变化 | 地表夜间辐亮度 | NASA Black Marble | 与人眼天空辉光不是同一指标 |
| 照明治理 | 遮罩、亮度、时段、光谱原则 | DarkSky、IES 及相关研究 | 原则不能直接换算成恢复星数 |
| 生态案例（若保留） | 具体事件前后鸟群或飞行观测 | 同行评议论文 | 避免把单一事件推广到所有鸟类 |

### 必须建立的证据边界

- 观测、模型、估计、情景四类内容在数据结构和画面标记上分开；
- 全球平均趋势不生成某城市的精确未来星数；
- 卫星地表辐亮度不直接换算肉眼可见星数；
- 天气、月相、大气透明度和个体视力不从长期光污染结论中消失；
- 没有来源的点位、指数和效果量不得进入新版。

## 9. 技术重构方向

若编辑方向获批，生产实现建议与最新《城市突然熄灯时》统一，迁移为独立 Svelte 5 / SvelteKit 静态故事：

```text
stories/disappearing-stars/
  src/
    components/
    data/
    routes/
    styles/
  static/
    data/
    docs/
  docs/
  scripts/
  package.json
  svelte.config.js
```

技术原则：

1. 数据、派生故事状态、纯视觉渲染、滚动状态和正文分离；
2. 使用可复用 `Scrolly` 组件和 `position: sticky`；
3. 真实星表在构建阶段预处理，不在浏览器中加载整套原始目录；
4. 同一恒星 ID 在所有章节保持对象恒常；
5. Canvas 或 SVG 只负责渲染，数值与状态来自独立数据模块；
6. 桌面与移动端分别设计场景，不用单纯 CSS 折行代替移动设计；
7. 提供静态首帧、无观察器回退、低动态版本和文字等价说明；
8. GitHub Pages 继续作为唯一正式发布目标。

技术迁移不是本阶段的交付。新版总体设计、详细故事板、内容证据包分别确认后才进入生产编码。

## 10. 建议体量

- 活跃阅读时间：8—10 分钟；
- 实质性发现：6 个；
- 主视觉系统：1 套；
- 主要滚动叙事：2 段；
- 分析性交互：1 个（地点/阈值探索，具体形式在总体设计阶段确定）；
- 机制互动：1 个（照明光路 A/B，不输出无依据指数）；
- 辅助图：最多 3 个；
- 方法、数据字典、处理脚本和来源独立保存。

目标不是增加图表数量，而是让读者连续完成六次有证据的认识变化。
