# 《消失的星空》总体叙事与视觉设计 v2

> 文档性质：结构性重构第二阶段总体设计
> 设计基线：`03-restructure-diagnosis-v1.md`
> 状态：总体设计已于 2026-07-28 确认；已进入详细故事板与关键帧设计
> 日期：2026-07-28

## 1. 设计结论

新版不再做一篇由多个光污染知识模块拼成的网页，而是让读者沿着同一批真实恒星，完整经历一条可见阈值的移动：

> 城市仍然保留最亮的几颗星，因此夜空看起来似乎没有改变；真正的损失发生在亮星之间——天空背景每抬高一点，大量较暗恒星就跨过肉眼边界。

整篇故事只有一个核心视觉系统：

- 开场中的恒星来自真实星表；
- 这些恒星在星座、星等分布、18 年情景和城市空间中保持同一 ID；
- 光污染不再表现为随机星点淡出，而是一条可解释、可测量、带有不确定性的阈值移动；
- 地图、时间和照明机制都服务于“为什么这颗星跨过了边界”，不再各自成立为独立小工具。

## 2. 受众与编辑承诺

### 受众

- 对夜空、城市、环境或天文有兴趣，但不需要具备天文学背景的中文读者；
- 长期生活在大城市、已经把稀疏星空视为“正常夜空”的读者；
- 希望理解数据来源和不确定性的进阶读者。

### 编辑承诺

读者不需要先理解星等、辐亮度或天空辉光。故事先让他们认出一片星空，再用一颗具体恒星教会第一个编码，最后才展开真实星表和城市数据。

页面承诺：

1. 所有恒星位置、名称和视星等来自可追溯星表；
2. 观测、模型、估计和叙事情景在视觉上明确区分；
3. 不把全球趋势写成纽约或深圳的精确预测；
4. 不把卫星地表夜光直接换算成肉眼可见星数；
5. 没有定量模型支撑的照明建议不输出“恢复多少颗星”或综合指数；
6. 不操作任何互动的读者仍能获得完整论证。

## 3. 核心问题、论点与张力

### 驱动问题

> 当城市夜空只“亮了一点”，为什么我们会失去这么多星？

### 暂定论点

> 人工天空辉光推动一条可见阈值穿过真实星空；由于较暗恒星的数量远多于亮星，阈值的小幅移动会造成不成比例的星空损失，而仍然可见的亮星又会掩盖这种变化。

### 张力

一个合理的直觉是：

> 只要熟悉星座还看得见，夜空就没有发生太大变化。

故事要让读者亲眼发现：

> 熟悉星座的骨架可以继续存在，但骨架之间的大部分星空已经被擦掉。亮星是变化的幸存者，也因此成为变化最好的伪装。

## 4. 标题与副标题

### 主标题

> **消失的星空**

### 副标题

> 城市只把夜空照亮一点，为什么数百颗星就越过了肉眼的边界？

### 中心句

> 星星没有消失。消失的，是我们与它们之间的对比。

原版“星星没有消失。消失的，是夜晚。”保留在结尾回环处；新版中心句在前半段承担更精确的解释任务。

## 5. 具体开场

### 开场对象

一个固定日期、固定时刻、固定观测方向中的猎户座天区。

暂定使用纽约冬夜作为主观察框架，因为：

- 猎户座对非专业读者辨识度较高；
- 亮星、腰带三星和较暗结构同时存在，适合教学；
- 纽约已有现成的城市—公园—海岸—较暗参照地空间主线；
- 便于把地点数据、照明机制和潜在生态案例放在同一地理世界中。

正式日期、时刻、方位和天区边界将在证据阶段根据可见高度、星表覆盖与移动端辨识度确定。

### 开场动作

首屏先显示城市条件下仍可看见的少数亮星。连接线不立即出现，标题也不遮住星体。

第一段短文只问：

> 这就是完整的猎户座吗？

向下滚动后：

1. 三颗腰带亮星被点名；
2. 一颗较暗、城市中容易失去的恒星出现空心位置标记；
3. 天空背景变暗；
4. 同一坐标上的更多恒星返回；
5. 星座线最后才出现，让读者发现自己先前看见的只是骨架。

开场不让读者拖动，不放地图、年份和方法按钮。先建立识别、预期与第一次反转。

## 6. 中央视觉名词、动词与比较框架

### 视觉名词

> 同一片真实天区中的恒星。

每颗恒星拥有稳定 ID、天空坐标、视星等、颜色信息、名称状态和证据来源。

### 视觉动词

> 跨过阈值。

恒星不会随机飞走或被替换。它们在固定坐标上：

- 失去对比；
- 变为空心位置；
- 移入星等轴；
- 跨过可见阈值；
- 在不同年龄或地点状态中消失或返回；
- 最后回到开场坐标。

### 稳定比较框架

- 固定天区；
- 视星等轴；
- 可见阈值；
- 观测地点；
- 数据证据等级。

### 注释声音

注释不使用“这里展示”“选择镜头”等制作语言。它直接回答：

- 哪颗星还在？
- 哪颗星刚刚跨过边界？
- 阈值移动了多少？
- 这个状态来自观测、模型还是情景？

## 7. 八章叙事结构

### 第一章：你看到的不是完整星座

**问题：**熟悉星座还在，是否意味着夜空没有改变？

**发现：**城市留下了猎户座最亮的骨架，却抹去了骨架之间的结构。

**视觉：**城市状态下的猎户座逐步恢复为较暗夜空；所有星保持固定坐标。

**证据：**真实星表、固定日期与投影。

**章节出口：**

> 最亮的星没有说谎。它们只是没有告诉你，周围少了什么。

### 第二章：一条看不见的边界

**问题：**为什么某颗星能看见，旁边一颗却消失？

**发现：**决定可见性的不是星星单独有多亮，而是它与天空背景之间还剩多少对比。

**视觉：**

1. 隔离一颗亮星和一颗较暗星；
2. 暂时放大星点与背景；
3. 引入视星等；
4. 把两颗星放到亮—暗轴；
5. 一条“肉眼可见阈值”进入画面。

**教学原则：**先比较两颗星，再解释星等数字越小越亮，避免把完整科学坐标一次性交给读者。

### 第三章：小幅变亮，大量消失

**问题：**阈值只移动一点，为什么星数会大幅减少？

**发现：**较暗恒星数量迅速增加，因此阈值扫过较暗端时，会一次跨过大量恒星。

**视觉：**

1. 开场恒星从天空坐标移动到星等轴；
2. 保持每颗星的 ID；
3. 更多同一天区恒星加入；
4. 恒星按星等排列；
5. 累计数量曲线出现；
6. 阈值移动，跨线恒星变为空心标记；
7. 这些空心标记返回天空坐标，形成缺失的星空。

**中央揭示：**

> 夜空损失不是一颗颗均匀发生。阈值越接近暗星密集区，下一点天空辉光就会抹去更多星。

正式数字在数据阶段计算，不在设计阶段预设。

### 第四章：一代人的夜空

**问题：**每年难以察觉的变化，在 18 年中会累积成什么？

**发现：**复合增长移动的是同一条阈值；熟悉亮星长期幸存，让记忆低估变化。

**视觉：**

- 时间从 0、6、12、18 岁推进；
- 同一组恒星持续存在；
- 阈值按论文情景函数移动，而不是线性插值；
- 页面同时显示天空状态、阈值和可见星数；
- 估计范围使用带宽或区间，不只显示单点数字。

**证据边界：**

- 使用 Globe at Night 2011—2022 全球人眼观测趋势；
- 这是全球平均变化情景，不是纽约预测；
- 天气、月相、个体视力不进入长期趋势计算，但在视觉旁明确标注。

### 第五章：一座城的多片天空

**问题：**城市中心、公园、海岸和都市圈外，看的是不同星空吗？

**发现：**天上的恒星没有改变，改变的是地点对应的天空背景和阈值。

**主结构：**纽约亮度剖面。

默认策划路线：

1. Times Square；
2. Central Park；
3. Jamaica Bay；
4. Pelham Bay；
5. 都市圈外较暗参照地。

地点名单可在数据阶段调整，不能为了沿用旧版而保留缺乏可靠数值的点位。

**视觉：**

- 桌面端：真实地图/空间剖面与固定星空并置；
- 手机端：星空置顶，地点以路线节点和简化剖面依次进入；
- 每个点位显示模型年份、数值区间、附近公众观测覆盖和证据等级；
- 云、月相和当晚天气不被包装成长期地点属性。

**作者路径到探索：**

先按五个策划节点滚动，教会地点差异；章节后半才开放点位选择。读者不操作也能获得完整路径。

若深圳数据能在同一模型、同一分辨率和同一处理流程中可靠提取，可作为探索中的第二条策划路线；不在总体设计阶段强行承诺双城。

### 第六章：光从地面来到天空

**问题：**一颗星为什么会因为地面路灯而跨过阈值？

**发现：**直接向上光、反射光、光谱与大气散射共同抬高背景；卫星和人眼因此测量不同结果。

**视觉转场：**

1. 保留第五章中一颗刚刚消失的恒星；
2. 画面向地平线下移；
3. 同一背景辉光被拆成直接上射、地表反射与大气散射路径；
4. 卫星视角从上方进入，人眼视角从地面进入；
5. 两把尺子在同一光路中出现，而不是做成两张信息卡。

**方法说明：**

- 人工天空亮度图用于长期空间基线；
- Globe at Night 更接近人眼星空体验；
- NASA Black Marble 记录离开地面的夜间辐亮度；
- 三者相关但不能直接互换。

### 第七章：让哪一些星回来

**问题：**不关闭城市，哪些照明改变能够减少无效上射光？

**发现：**用途、方向、亮度、时段与光谱改变的是光路；星空改善是这些改变经过大气后的结果，不应被任意打分。

**互动：照明 A/B 光路比较**

默认比较：

- 未遮罩灯具；
- 完全遮罩并向下定向的灯具。

逐步加入：

- 必要亮度与过量亮度；
- 全夜照明与按时段调暗；
- 暖色与高短波成分光源。

控件改变真实工程维度，画面展示哪些光路被减少。只有在数据阶段找到可信模型并完整记录假设时，才将光路变化进一步换算为天空亮度区间；否则不显示恢复星数。

**生态证据：**

若正式证据审计确认一个纽约具体事件拥有可复核的鸟群观测量，可用一段静态证据插页说明同一束上射光的生态后果。它不成为新互动，也不改变主视觉语法。若证据不足则删除，不影响主线。

### 第八章：回到今晚

**问题：**当读者再次看见开场猎户座，会看见什么不同？

**发现：**亮星组成的骨架不再代表完整夜空；读者已经能识别阈值、证据和可改变的光路。

**视觉：**

- 回到开场的同一天区、同一投影和同一星 ID；
- 城市状态、较暗状态和证据区间依次叠合；
- 那颗在第二章被选中的较暗星再次出现；
- 不提供新的复杂控件；
- 结尾恢复留白和安静节奏。

**结尾方向：**

> 星星没有消失。
> 消失的，是夜晚让我们看见它们的能力。

> 城市不必变成全黑，才有可能把一部分夜晚还回来。

## 8. 视觉状态阶梯

| 状态 | 语义操作 | 读者学到什么 |
|---|---|---|
| S0 城市猎户座 | 实例化 | 这是我们要追踪的真实天区 |
| S1 亮星骨架 | 标注 | 熟悉星座仍在 |
| S2 暗星返回 | 揭示 | 原先看见的不是完整星空 |
| S3 两颗星 | 隔离 | 不同亮度的星在同一背景中命运不同 |
| S4 星等轴 | 对齐与编码 | 每颗星可以按亮度比较 |
| S5 可见阈值 | 标注 | 阈值决定可见与不可见 |
| S6 恒星群与累计曲线 | 复制与聚合 | 较暗端聚集着更多恒星 |
| S7 阈值移动 | 重排与揭示 | 小幅移动跨过大量恒星 |
| S8 18 年状态 | 时间化 | 缓慢变化如何骗过记忆 |
| S9 城市路线 | 地理化 | 地点改变背景，不改变天上的星 |
| S10 地面光路 | 机制化 | 阈值为什么被推高 |
| S11 A/B 照明 | 比较与测试 | 哪些工程选择减少无效光路 |
| S12 回到猎户座 | 返回 | 开场星空获得新的意义 |

状态之间不更换数据实体。只有进入光路机制时，恒星退为结果标记；它仍保持身份并在结尾返回。

## 9. 交互策略

### 9.1 作者引导优先

前四章不开放自由探索。滚动顺序承担教学：

> 认出星座 → 发现缺失 → 学会星等 → 看见阈值 → 理解非线性。

### 9.2 第一次交互：城市路线

地点选择回答真实读者问题：

> 从城市中心向外移动，同一片星空会怎样改变？

控件改变真实点位和相应数据区间，而不是切换装饰性场景。

### 9.3 第二次交互：照明 A/B

控件改变真实照明设计维度。默认 A/B 已能说明结论；不要求点击才能继续。

### 9.4 不采用的互动

- 不要求读者拖动首屏才能看到标题；
- 不制作全球空白搜索框；
- 不把滑杆作为进入下一段的门；
- 不自动循环星空消失；
- 不把任意综合分数包装成实验结果；
- 不让读者“拯救星星”以游戏化反馈换取成就。

## 10. 证据、方法与不确定性

### 10.1 四类证据标记

| 类型 | 页面标签 | 视觉处理 |
|---|---|---|
| 观测 | 公众观测 / 卫星观测 | 实心标记 |
| 模型 | 天空亮度模型 | 细网纹与年份 |
| 估计 | 由数据转换的区间 | 半透明带与范围 |
| 情景 | 全球趋势转译 | 虚线边界与“情景”标签 |

### 10.2 关键限制

- 星表告诉我们天上有哪些星，不保证某人当晚能看到；
- 极限星等受视力、适应时间、透明度、月相和局部眩光影响；
- 人工天空亮度地图是时间截面和模型，不是实时天气；
- 全球 9.6% 趋势存在地区差异；
- 地面夜光、天空辉光与肉眼星数没有一条无条件通用的换算式；
- 照明设计的方向性结论不能自动换算为某城市恢复多少颗星。

### 10.3 方法入口

- 第一次出现视星等时提供一句紧凑解释；
- 第一次出现地点数据时显示模型年份和空间分辨率；
- 第一次并置卫星与人眼时提供证据剖面；
- 完整方法、数据字典、处理脚本、来源和下载位于结尾方法模块。

## 12. 移动端总体设计

移动端不是桌面双栏的折叠版。

### 开场

- 星图占上方 58—64svh；
- 标题和短文位于下方独立层，不覆盖关键星体；
- 星座名称只保留 2—3 个主动标签；
- 星座线在揭示状态才出现。

### 阈值 scrolly

- 上方为 sticky 星图；
- 下方每个步骤控制一个离散状态；
- 星等轴在手机端改为纵向亮度梯，不压缩成过密横轴；
- 当前阈值以大号直接标签显示。

### 城市路线

- 先显示当前地点的星空；
- 下方使用路线节点与距离剖面，不把完整地图缩到无法辨认；
- “查看地图”作为展开层；
- 点位按钮至少 44px，支持左右滑动和键盘。

### 照明 A/B

- 默认上下对照，不使用左右分屏；
- 控件按方向、亮度、时段、光谱分组；
- 每次只展开一组，避免控制台式界面。

### 手机性能

- 星表在构建时裁剪；
- Canvas 设备像素比设上限；
- 滚动只更新离散故事状态；
- 不做逐帧 DOM 星点；
- 背景页面不可见时停止渲染。

## 13. 无障碍与等价阅读

- 页面有语义标题和自然线性顺序；
- 每个主视觉提供可读名称和当前结论；
- 恒星状态不只靠透明度：可见为实心，不可见为细环或位置刻度；
- 阈值使用线型、标签和位置，不只靠颜色；
- 所有地点和 A/B 控件可键盘操作；
- 焦点状态清晰；
- 触控目标至少 44×44px；
- `prefers-reduced-motion` 使用离散状态切换，不删除中间解释；
- IntersectionObserver 失败时显示静态关键帧；
- 无 JavaScript 时依次显示城市星空、较暗星空、星等分布、18 年四状态、五地点比较与 A/B 光路图；
- 提供数据表列出开场天区每颗标注恒星的名称、视星等和各情景可见状态。

## 14. 技术架构

新版完整采用当前 Pudding Svelte 5 starter 的架构模型，并适配 DataSlices 仓库：

### 框架

- Svelte 5；
- SvelteKit；
- `@sveltejs/adapter-static`；
- 静态预渲染；
- GitHub Pages 子路径；
- Vite 构建。

### 状态层

```text
原始数据
  ↓
规范化数据
  ↓
Svelte 5 runes 派生故事状态
  ↓
纯星空 / 分布 / 地图 / 光路渲染器
  ↓
sticky scrolly 与读者控件
  ↓
正文、方法和来源
```

### 滚动

- 复用与 Pudding starter 同型的 `Scrolly.svelte`；
- IntersectionObserver 比较步骤可见比例；
- CSS `position: sticky`；
- 原生文档滚动；
- 离散故事状态为主；
- 只有阈值连续移动等真正连续现象使用局部 progress；
- 向上滚动恢复先前状态。

### 渲染

- 恒星主体：Canvas；
- 星名、阈值、焦点和无障碍状态：SVG/HTML 覆盖层；
- 地图：SVG 或轻量 Canvas，最终由数据规模决定；
- 不使用 3D、WebGL 星空或装饰性粒子。

### 数据构建

- Python/Node 处理脚本下载或读取固定版本源数据；
- 输出裁剪后的 `stars.json`、`sky-states.json`、`nyc-transect.json`、`evidence.json`；
- 每个输出包含来源版本、下载日期、单位和处理说明；
- 构建期间验证恒星 ID、数值范围、空值和证据类型；
- 浏览器不现场推断或生成替代数据。

### 组件边界

```text
Story.svelte
  HeroConstellation.svelte
  ThresholdScrolly.svelte
    StarField.svelte
    MagnitudeRail.svelte
    ThresholdAnnotation.svelte
  GenerationScrolly.svelte
  CityTransect.svelte
  LightPathExplainer.svelte
  LightingComparison.svelte
  Methods.svelte
  ReadingProgress.svelte
```

组件名称可在实现阶段调整，但数据、状态、视觉和正文的边界不得合并回单文件脚本。
