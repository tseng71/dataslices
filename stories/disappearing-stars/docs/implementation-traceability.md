# 《消失的星空》设计—实现追溯表

> 目的：记录每个设计模块对应的代码、数据、当前完成度和下一步。网页实现不得仅依赖聊天上下文。

## 1. 当前实现依据

当前 `index.html`、`story.css` 和 `story.js` 最初是根据聊天中形成的 v1、v2 方案以及后补的压缩版 `story-design.md` 编写。由于完整 v1、v2 当时没有先进入仓库，开发过程缺少正式的版本化规格。这是流程缺陷。

从本文件提交开始，正式依据调整为：

1. `../../../docs/dataslices-overall-design.md`
2. `01-concept-design-v1.md`
3. `02-storyboard-wireframes-v2.md`
4. `manuscript.md`
5. `methodology.md`
6. `sources.md`

后续网页修改必须同步更新本表。

## 3. 文件职责

### `index.html`

负责：

- 章节顺序；
- 正文在网页中的拆分；
- 无障碍语义和控件；
- 方法与来源入口。

不得在 HTML 中写入与 `manuscript.md` 矛盾的核心事实。

### `story.css`

负责：

- 视觉层级；
- 桌面和手机布局；
- 动效的表现层；
- 字体、留白与主题色。

视觉变更若改变叙事节奏，应先更新 v2 故事板。

### `story.js`

负责：

- 星空渲染；
- 滚动状态；
- 滑杆和地点互动；
- 情景模拟；
- 性能和事件管理。

任何数字模型必须在 `methodology.md` 记录公式、假设和限制。

### `data/`

负责保存：

- 正式公开数据或经许可的处理结果；
- 数据字典；
- 版本、年份和许可证；
- 处理脚本输出。

当前 `locations.json` 与 `sky-scenarios.json` 是原型情景，不应被描述为实测数据。

## 5. 后续开发顺序

1. 下载并处理真实星表，替换所有合成星点；
2. 决定地点模块采用真实城市点位还是环境类型；
3. 获取并处理人工天空亮度和夜光数据；
4. 重做真实地图；
5. 校准 250→100 情景公式；
6. 完成网页引用与方法入口；
7. 进行桌面与手机浏览器测试；
8. 进行阅读时长测试；
9. 将仓库设为 public 并启用 GitHub Pages；
10. 发布 v1.0 tag。

## 6. 变更规则

- 每次重要视觉或数据改动，在本文件增加一条状态更新；
- 设计与实现不一致时，以最新已批准的设计文档为准；
- 若实现发现数据无法支持设计，先修改设计稿和方法文档，不得静默用演示数字替代；
- 正式发布 commit 必须在 README 中记录。
