# 《消失的星空》概念设计稿 v1

> 文档性质：第一版完整制作方案的仓库化整理  
> 目标：确定故事定位、章节结构、主要互动、视觉系统和数据需求。  
> 状态：设计基线；后续由 v2 逐章线框细化。

## 1. 选题与核心表达

标题：

> **《消失的星空：一代人失去了多少颗星？》**

副标题：

> 从城市灯光到肉眼夜空，我们正在失去怎样的夜晚。

故事不是普通的光污染科普，而是把一个抽象环境问题转译为可以被读者感受到的个人经验：

> 星星没有消失。消失的，是夜晚。

读者离开页面时应记住三件事：

1. 城市居民看到的是经过人工灯光筛选的夜空；
2. 光污染变化缓慢，却足以在一代人的时间内明显改变可见星空；
3. 城市照明并非只有“开”与“关”，合理设计可以把一部分夜晚还回来。

## 2. 内容体量

- 目标活跃阅读时长：8—10 分钟；
- 正文目标：约 2,800—3,400 个汉字；
- 1 个全屏 Hero；
- 2 个大型核心互动；
- 4—6 个辅助图形；
- 一个个性化或可代入的结尾；
- 方法和来源独立保存。

## 3. 八个叙事模块

### 模块 0：沉浸式开场

**问题：城市夜空原本就是这样吗？**

画面：

- 全屏真实规则驱动的星空；
- 滚动时天空背景逐渐变亮；
- 暗星先消失，熟悉星座主星最后保留；
- 地平线城市光穹逐渐升高。

核心文案：

> 如果你长期住在大城市，你可能从未真正见过银河。

> 星星没有消失。消失的，是夜晚。

作用：在解释任何指标之前，让读者先亲眼经历一次“星空被擦掉”。

### 模块 1：一片天空究竟能看见多少星

设计一个五档天空质量互动：

1. 自然暗夜；
2. 乡村或远郊；
3. 城郊过渡；
4. 城市；
5. 市中心。

滑杆同时改变：

- 天空背景亮度；
- 恒星可见极限；
- 可见星的密度；
- 银河是否可辨认；
- 天空状态说明。

目的：建立全文共同使用的“可见极限”视觉语法。

### 模块 2：城市为什么会抹掉星星

解释四个连续步骤：

1. 地面灯光直接向上逸散；
2. 路面、玻璃和建筑反射灯光；
3. 大气分子、水汽和颗粒散射光线；
4. 天空背景变亮，星星与背景之间的对比下降。

主要视觉：城市剖面与光穹动画。

需要强调：更亮不自动等于更安全，问题是光是否有明确用途、是否投向正确位置、是否超过必要亮度。

### 模块 3：同一座城市，不只有一种夜空

首选案例：纽约；深圳作为第二城市或后续扩展。

地点建议：

- 时代广场；
- 中央公园；
- 牙买加湾；
- 佩勒姆湾公园；
- 都市圈之外的更暗参照地。

布局：左侧地图，右侧固定同一天区星空。点击地点后，只改变天空背景、极限星等和说明。

核心表达：

> 你住在哪里，决定了你能看见哪一个版本的宇宙。

### 模块 4：一代人的夜晚

原始构想曾考虑 1992、2000、2010、今天的本地时间滑杆，但该做法会暗示不存在的连续精确星数。

修正方案：

- 用 Globe at Night 的全球人眼观测趋势解释变化速度；
- 用 NASA Black Marble 展示 2012 年后的地面灯光变化；
- 用“孩子从 0 岁到 18 岁，250 颗变为约 100 颗”的情景转译全球平均变化率；
- 明确标注这不是任一城市的精确预报。

核心句：

> 这种变化不是一夜发生的。它慢到足以骗过记忆，却快到足以改变一代人的夜晚。

### 模块 5：谁还拥有真正的夜晚

不用排名条形图，而采用五到六个相同尺寸的“天空窗口”。

候选地点：

- 纽约核心区；
- 深圳中心区；
- 东京核心区；
- 普通郊区；
- 较暗海岸或乡村；
- 暗夜保护区。

比较规则：

- 同一天区；
- 同一投影；
- 同一恒星位置；
- 只改变天空背景和可见阈值。

这使比较公平，也避免使用拍摄条件完全不同的照片。

### 模块 6：消失的不只是浪漫

分为三个短章节：

1. **文化**：导航、节令、神话和公共记忆；
2. **生态**：夜间迁徙鸟类、昆虫和夜行动物；
3. **人类与能源**：眩光、无效向上光和照明质量。

生态主案例聚焦迁徙鸟类，避免铺陈过多物种而失去证据深度。

### 模块 7：夜晚可以回来吗

四项主要措施：

1. 灯具有明确用途；
2. 完全遮罩并向下定向；
3. 不超过必要亮度；
4. 深夜调暗或感应控制。

色温作为第五项控制。

交互模拟器同时展示：

- 地面照明是否仍满足用途；
- 向上逸散光相对变化；
- 光穹相对变化；
- 星空的方向性改善。

没有正式照明与大气模型时，不显示“恢复了具体多少颗星”的伪精确数字。

### 模块 8：你所在的地方，还剩多少星

理想版本允许输入城市或选择预设地点，输出：

- 城市环境类型；
- 可见星范围；
- 银河可见可能性；
- 更暗地点建议；
- 一句个性化结尾。

首版若数据覆盖不足，可退化为观察指南和地点选择，而不是编造城市结果。

## 4. 阅读节奏

| 阶段 | 预计停留 |
|---|---:|
| 开场与核心问题 | 45—60 秒 |
| 星数与可见极限 | 60—90 秒 |
| 物理机制 | 60—75 秒 |
| 同城地图 | 60—90 秒 |
| 代际变化与两把尺子 | 75—100 秒 |
| 多地比较 | 50—70 秒 |
| 生态与文化影响 | 70—100 秒 |
| 治理与结尾 | 70—100 秒 |

节奏采用“四次高潮、两次安静解释”：

1. 星星消失；
2. 250 颗变 100 颗；
3. 地图改变天空；
4. 治理后星空恢复。

机制解释和方法章节降低动画密度，让读者恢复注意力。

## 5. 视觉系统

### 色彩

- 自然暗夜：近黑深蓝；
- 城市天空：灰蓝与暖色光穹；
- 城市灯光：克制的琥珀色；
- 数据辅助色：灰蓝、青蓝；
- 正文：暖白，避免刺眼纯白。

### 排版

- 标题具有科学杂志或编辑设计气质；
- 正文宽度适合中文长读；
- 重点数字可占据整屏，但不可脱离语境；
- 章节转折使用大留白，不依赖卡片堆叠。

### 动效

- 星星因背景对比下降而淡出；
- 不使用爆炸、弹跳或装饰性粒子；
- 滚动动画可回退；
- 手机端使用点击和纵向布局，不依赖 hover。

## 6. 核心互动优先级

必须实现：

1. Hero 星星消失；
2. 可见极限滑杆；
3. 地点—星空联动；
4. 代际情景；
5. 结尾观察或个性化模块。

推荐实现：

6. 光散射剖面；
7. 多地同一天空；
8. 照明治理模拟器。

可简化为静态图：

- 文化历史；
- 部分生态说明；
- 方法和数据流程。

## 7. 数据层

需要的数据包括：

- 恒星位置与视星等；
- 人工夜空亮度模型；
- NASA Black Marble 地面夜间辐亮度；
- Globe at Night 人眼观测；
- 城市和地点地理数据；
- 迁徙鸟类研究；
- 负责任户外照明原则。

## 8. 关键科学修正

不得把 1992—2024 年制作成某地点“精确失去多少颗星”的连续滑杆，因为不同年代可用数据、传感器和测量对象不一致。

可靠表达应将以下内容分开：

- 星表：哪些星理论上可见；
- 人眼公众观测：天空视觉变化；
- 卫星夜光：地面灯光变化；
- 人工夜空亮度模型：空间基线。

这项修正是 v2 设计稿的基础。
